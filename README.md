# EventManager

ASP.NET Core Web API сервис для управления мероприятиями

## Основные возможности

Сервис предоставляет RESTful API для управления мероприятиями с базовыми CRUD-операциями

- Создание новых мероприятий с основной информацией (заголовок, описание, время)
- Обновление существующих мероприятий
- Удаление мероприятий
- Создание бронирования для мероприятия
- Swagger документация

Обработка бронирований выполняется в фоновом режиме с использованием BackgroundService

### Работа с бронированием мероприятий

#### Модель Booking

| Поле        | Тип           | Описание                            |
| ----------- | ------------- | ----------------------------------- |
| Id          | Guid          | ID бронирования                     |
| EventId     | Guid          | ID мероприятия                      |
| Status      | BookingStatus | Статус бронирования                 |
| ProcessedAt | DateTime?     | Дата и время обработки бронирования |
| CreatedAt   | DateTime      | Дата и время создания               |
| UpdatedAt   | DateTime      | Дата и время последнего обновления  |

#### Статусы бронирования (BookingStatus)

| Статус    | Описание                                                  |
| --------- | --------------------------------------------------------- |
| Pending   | Бронирование создано и ожидает обработки в фоновом режиме |
| Confirmed | Бронирование подтверждено                                 |
| Rejected  | Бронирование отклонено                                    |

#### Логика фоновой обработки бронирований

Обработку бронирований выполняет `BookingBackgroundService` в фоновом режиме:

1. **Поиск ожидающего бронирования** - сервис пытается получить бронирование в статусе `Pending`, которое было создано раньше других
2. **Имитация обработки** - если бронирование найдено, сервис имитирует операцию обработки, ожидая 2 секунды
3. **Подтверждение** - после паузы бронирование переводится в статус `Confirmed` и устанавливается дата `ProcessedAt`
4. **Повтор цикла обработки** - сервис повторяет цикл с задержкой в 1 секунду между итерациями
5. **Обработка ошибок** - исключения логируются, но не прерывают работу сервиса

#### Пример сценария бронирования

**1. Создание бронирования**

```http
POST http://localhost:5226/api/events/a4d47004-9eaf-4bdb-9ac5-32a9b79e7e71/book
```

Сервис немедленно возвращает ответ `202 Accepted` с идентификатором бронирования и текущим статусом `Pending`:

```json
{
  "id": "d4bbbd9f-80b6-42bf-9c3b-b23cea931709",
  "status": "Pending"
}
```

В заголовке `Location` указан URL для отслеживания бронирования:

```
Location: http://localhost:5226/api/bookings/d4bbbd9f-80b6-42bf-9c3b-b23cea931709
```

**2. Ожидание обработки**

Фоновый сервис `BookingBackgroundService` обнаружит бронирование со статусом `Pending`, выдержит паузу и подтвердит его  
В среднем обработка занимает от 2 до 3 секунд (с учетом периодичности опроса в 1 секунду)

**3. Проверка статуса**

```http
GET http://localhost:5226/api/bookings/d4bbbd9f-80b6-42bf-9c3b-b23cea931709
```

Ответ `200 OK`:

```json
{
  "id": "d4bbbd9f-80b6-42bf-9c3b-b23cea931709",
  "eventId": "a4d47004-9eaf-4bdb-9ac5-32a9b79e7e71",
  "status": "Confirmed",
  "processedAt": "2026-09-26T14:35:14.07Z",
  "createdAt": "2026-09-26T14:35:11.15Z",
  "updatedAt": "2026-09-26T14:35:14.07Z"
}
```

Статус изменился на `Confirmed`, а `processedAt` содержит дату и время подтверждения

## Технологии и архитектура

- **Язык**: C#
- **Фреймворк**: .NET 10
- **Документация**: Swagger
- **Архитектурный стиль**: RESTful
- **Формат данных**: JSON

### Структура проекта

- **EventManager.Domain**: доменные модели бизнес-логики
- **EventManager.Application**: бизнес-логика, DTO модели, маппинг
- **EventManager.WebApi**: HTTP контроллеры, обработка ошибок в запросах

## Запуск сервиса

### Предварительные требования

- .NET 10 SDK
- Git

### Шаги для запуска

#### 1. Клонирование репозитория

```bash
git clone https://github.com/Evgeniy-Efimov/event-manager.git EventManager
cd EventManager
```

#### 2. Запуск API

```bash
dotnet run --project EventManager.WebApi
```

#### 3. Проверка работы

Swagger UI будет доступен по адресу http://localhost:5226/swagger/index.html
